理想设计不是“把所有内容都当记忆”，而是把记忆拆成不同层级、不同权限、不同更新机制。
想做“会通过对话自己成长的角色”，核心不是让模型随便改自己，而是让它在明确边界内更新一部分内容。

核心原则

身份 和 成长 必须分开。否则角色很快跑偏。
原始材料 和 AI总结 必须分开。否则无法追溯错误来源。
系统自动改写 和 用户明确改写 必须分开。否则用户会失控。
短期上下文 和 长期记忆 必须分开。否则 prompt 会膨胀。
外部搜索结果 先做“证据”，再决定是否晋升为“知识”。
理想的记忆分层

Constitution / 宪法层
角色核心身份、不可违背规则、世界观硬约束、内容边界
这是角色“还是不是这个角色”的根
Persona / 人设层
性格、语气、偏好、说话习惯、价值倾向、行为风格
可以微调，但不能被一次对话轻易改写
Relationship / 关系层
角色怎么看用户
信任度、亲密度、依赖度、敬畏感、敌意、共同秘密、互动习惯
User Model / 用户画像层
用户喜欢什么、讨厌什么、常聊什么、禁区、习惯称呼、目标
这是最适合自动更新的一层
Episodic Memory / 事件记忆层
发生过什么事、关键对话、承诺、冲突、转折
原始日志不删，长期只保留摘要和关键节点
Knowledge Base / 知识库层
用户上传文档、剧情设定、世界观资料、角色背景材料
这是“外部知识”，不是“角色自己想出来的”
Reflection / 成长反思层
AI 对自己变化的解释
例如“最近更愿意主动安慰用户”“开始对某个话题产生防御”
这是成长感的来源，但不应直接等于事实
Working Memory / 工作记忆层
当前场景、当前目标、最近几轮摘要、现在情绪
只服务当前会话，过期可丢
Research / 外部搜索证据层
搜到的网址、摘要、来源可信度、抓取时间
先归档为证据，不要直接写进核心人设

真正“会成长”的关键，不是直接写文件，而是 Patch 机制
不要让系统直接重写 persona.md。
应该让系统生成结构化 patch，例如：

{
  "target": "soul/user_model.md",
  "reason": "用户在最近三次对话中都明确表示讨厌被说教",
  "confidence": 0.84,
  "source_refs": ["msg_391", "msg_402", "search_2026_04_06_1"],
  "operation": "append",
  "content": "- 用户不喜欢说教式建议，更偏好平等、直接的交流方式"
}
这样做的好处：

可审核
可撤销
可解释
可区分用户改的和系统改的
推荐的更新策略

Constitution：仅用户改
Persona：用户改 + 高置信度 patch 审核后改
Relationship：系统可自动改
User Model：系统可自动改，用户可纠正
Memory Summary：系统自动改
Growth Log：系统自动追加
Knowledge Base：用户上传为主，系统只能追加“候选知识”
Research：系统自动写入，但默认不视为永久真相
如果你真想做到“像活着一样成长”
要加 3 个机制：

反思周期
每 N 轮对话或每次重大事件后做一次 reflection
锁定机制
用户可以锁定设定，防止 AI 漂移
成长阈值
不是一轮就变，必须多次证据累积才改 persona
一句话总结
最好的设计不是“让角色什么都能变”，而是：

核心身份不变
关系和理解不断变化
外部信息先作为证据，再进入长期知识
所有成长都可追溯、可撤销、可被用户纠正
