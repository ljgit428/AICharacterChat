# Version 0.1.2 - Memory System v2, Natural Chat & Dedicated Settings

## Release Date
August 2026

## Overview
Version 0.1.2 is the largest release since v0.0.5: it ships the first three phases of the memory system v2 (reliability, growth, visibility), introduces WeChat-style natural chat messaging on the frontend, rebuilds the chat experience around a Discord-style page with per-reply token usage, moves model/user settings to a dedicated `/settings` route, and adds per-character web search with a research-to-memory bridge. Design work is captured in two new specs under `spec/`.

Roughly 46 files changed with ~5,200 insertions across backend (Django/Celery) and frontend (Next.js/React).

## ✨ New Features

### Chat Experience
- **Discord-style chat page** (`/chat`): independent session pools per character with a dedicated sidebar, separate from the workspace view.
- **Natural chat queue (Phase A)**: sending is always available — messages sent while the character is replying are queued ("待发送" style) and dispatched automatically; consecutive quick sends are merged into one turn; stop is demoted to a safety fuse on the streaming bubble.
- **Tool calls & native reasoning in stream**: streamed replies now surface tool-call activity and native reasoning traces; fixed buffered tool-path streaming to emit dict delta events.
- **Token usage ring**: every reply's token usage is captured and persisted; the composer shows a context-usage ring with hover details, powered by a new per-model context-window setting for accurate percentages.
- **One-time auto topic titles** with manual rename support.
- **Unified topic/chat mode switch** across all sidebar headers.
- **Meta events out of speech bubbles**: memory updates and other system events render as layered meta entries instead of fake chat bubbles.

### Memory System v2 (phases 1–3)
- **Phase 1 — Reliability**: fixed silent loss of the first user message, added broker-down degradation so memory extraction no longer disappears when Celery isn't running, removed the 900-character injection truncation that made memories invisible to the AI, tool errors no longer abort the whole extraction task, and API errors are never fed into the extraction prompt.
- **Phase 2 — Growth**: relationship state and shared-milestone sections as structured memory sections.
- **Phase 3 — Visibility**: `/memory` page gained growth timeline cards, milestone highlights, and an "AI view" modal showing exactly what narrative the AI sees.

### Web Search & Research Bridge
- **Per-character web search toggle** with Tavily; durable facts from search results flow into long-term memory (research-to-memory bridge).
- **Graceful degradation**: missing or invalid keys produce clear readiness hints instead of hard failures.

### Settings Page
- **Dedicated `/settings` route**: left sidebar navigation between User Settings and API Settings (with ready/required badge), keeping the original split-panel layouts; home sidebar and chat sidebar both link to it, replacing in-home settings views.

### Character Management
- Hardened folder-import pipeline (issues found via real-model GUI testing).

## 🐛 Bug Fixes
- Stabilized memory audit log ordering with an id tiebreaker in tests.
- Shared one generation config between streaming and non-streaming paths to prevent behavioral drift.
- Fixed dict-delta emission from buffered tool-path streaming.
