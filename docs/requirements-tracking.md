# 需求/问题记录

本文件记录已确认但尚未实施的需求与问题，供后续版本排期参考。
格式：`## [状态] 标题` — 背景 / 期望行为 / 建议方案（可多选）。

## [已确认，待排期] 角色回复长度控制：有时需要长回复，有时需要短回复

- **记录日期**：2026-08-27
- **来源**：GUI 实测（天童爱丽丝会话）——角色长回复（如推荐游戏清单）常整段输出，
  用户反映"有时候需要说那么长，有时候又不需要那么长"。
- **现状**：系统提示词构建（`chat/soul.py` 的 `build_character_system_prompt_preview`
  与 prompt 组装）中**没有**任何回复长度控制，回复长度完全由模型自由发挥。
- **期望行为**：
  - 角色级"回复风格"偏好（话痨 / 标准 / 简洁），注入系统提示词，让说话量符合人设；
  - 消息级快捷控制（输入框上方"简短 · 标准 · 详细"芯片），只对当轮生效，可覆盖角色默认；
  - 软引导自动适配：回复长度与用户消息大致相当（用户简短则简短）。
- **建议方案**：
  1. 角色表单新增"回复风格"下拉，存角色字段（或注入 `response_guidelines` 头部），
     `build_character_setup_markdown` 按设置注入一条准则；
  2. 请求参数带 `length_mode`（short/standard/detailed），在当轮 prompt 尾部覆盖注入；
  3. 前端：角色表单下拉 + 聊天输入框上方三个芯片（复用"实时"按钮的样式）。
- **明确不做**：事后的"太长/太短"反馈按钮（模型无法优雅重说，体验差成本高）。

## [已确认，待排期] 角色头像进入记忆系统：补充大模型图像描述文本

- **记录日期**：2026-09-03
- **来源**：v0.1.5 修复"角色头像 webp 上传后不显示"（`e452369`）时顺带发现——
  头像目前只作为展示图片（`avatars/` 桶、`avatar_url` 字段），**没有任何内容语义**。
- **现状**：角色头像仅存 URL，模型看不到图片内容；参考资料里"图片会作为视觉参考"
  （`CreateCharacterSimplifiedForm` 上传区文案）仅用于资料文件，头像不参与。
- **期望行为**：
  - 头像接入记忆系统：用户设置/角色上传头像时，让大模型生成一段图像描述文本
    （外观、服装、氛围等），随 `avatar_url` 一并保存；
  - 描述注入角色设定（如 `build_character_setup_markdown`），让角色"知道"自己的
    外貌、能在聊天中描述自己，也让记忆系统可作为可引用事实；
- **建议方案**：
  1. 上传后调用现有的 `generateCharacterDraft` 同款图像理解管线（后端已支持
     `image/*` 的 Anthropic/OpenAI 视觉输入，`chat/tasks.py` 白名单含 webp）；
  2. 在 `AvatarCropper` 应用回调或后端上传端点异步生成描述，存新字段（如
     `avatar_description`），角色序列化器（`CharacterSerializer`）暴露；
  3. 提示词组装时把描述作为"角色外貌"一节（可选开关），避免占用视觉上下文预算。
